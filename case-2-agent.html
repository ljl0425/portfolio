转折

我动的不是「上个大模型」—— 是先分清这条链路上哪一段模型能判、哪一段必须留给人，再一段一段划边界。

03

关键决策点

三个，不多不少

D1

我选择：判定权给模型，执行权不给

放弃的选项

模型判完直接执行：全自动放行、自动 Hold，人力能压到最低。

放弃理由：错判一条放行，损失的是一批货；人复核一条只要几秒。这笔账不对称。

代价

能自动结掉的是「判据已经写清」那一部分，剩下的重单还是要人坐在决策位上；自动结单的比例能爬到多高，取决于规则库攒得多细。

D2

我选择：不确定就升级人工，不做兜底猜测

放弃的选项

让模型「再想一次」补一个答案，追求每一单都有输出。

放弃理由：实际跑下来兜底几乎全错，而且错的时候语气一样自信 —— 这种输出比没有输出更危险。

代价

人工介入率到不了 0，永远有一部分单需要人看一眼；早期这个比例还不低。

D3

我选择：用编排平台搭，不自己写 Agent 框架

放弃的选项

自研一套 Agent 框架：能力不受限，想怎么改就怎么改。

放弃理由：我要的是能快速改节点、加分支，而且业务同事看得懂；不是再维护一个框架。

代价

受平台能力边界限制，复杂逻辑要拆成多段链路；可读性换来了灵活性，也换来了迭代速度。
